# 产品与架构说明

## 产品原则

1. **确认优先**：先识别和预览，再由用户触发填写；提交永远留给用户。
2. **本地优先**：个人档案、站点规则和操作记录默认留在浏览器本地。
3. **事实约束**：AI 可以突出重点和改善表达，但不能替用户创造履历。
4. **最小权限**：默认只使用 `activeTab`；不要求永久读取所有网站。
5. **可恢复**：填写前保存页面原值，后续版本提供一键撤销本轮填写。

## 组件

```text
选项页
  ├─ 简历本地解析（PDF / DOCX / Text）
  ├─ 个人档案编辑与校对
  └─ AI 提供方、模型与授权设置

弹出页 ──用户点击──> 当前标签页临时权限
                         │
                         ▼
内容脚本
  ├─ 收集可见且空白的表单控件
  ├─ 组合 label / aria / placeholder / name 等语义
  ├─ 确定性分类、冲突检测与必填人工降级
  ├─ Shadow DOM 预览面板
  └─ 模拟 input / change / blur 事件填写

后台 Service Worker
  ├─ 读取本机档案
  └─ 保管 API Key，并代理显式触发的 AI 请求
```

## 下一阶段建议

### P0：真实网站兼容性

- 已实现站点适配器注册表：通用规则、Moka、北森、字节跳动、腾讯和阿里巴巴按域名选择标签和忽略规则。
- 已补 Moka 和北森适配器边界；2026-10-10 只读验证到 Moka、北森和字节的公开职位详情及申请入口，三者均在进入真实申请表前要求登录，因此没有真实字段级准确率证据。
- 已实现动态表单观察：用户展开“添加项目/经历”后会自动刷新当前识别结果；DOM 变化、iframe 加载以及页面 input/change 活动会先使重复行绑定失效。
- 已实现最近一轮填写撤销：填写前记录控件原值，页面仍存在时可以回退。
- 已实现置信度和歧义分层：只有确定结果进入可填写列表，可见必填的未知/冲突/缺值项单独显示为人工处理。
- 已实现城市/详细地址分离、单选/多选精确选项匹配；输入类型不能压过冲突 label。同一 document/form 的原生 radio 若复用 `name` 并跨越多个重复根，会因浏览器原生互斥风险整组转人工；checkbox 可按重复根隔离，但任何同名成员已有选择或归属不唯一时整组转人工。
- 已有匹配项可通过下拉框纠正，并按域名、控件类型与多路字段证据组成的指纹保存在本机，避免仅凭同名标签误复用；下一步是让未知必填项也能显式建立纠正规则。
- 重复教育、工作、项目和获奖行只有在用户把页面行显式绑定到一条结构化记录后才会进入填写列表；未绑定、记录已删除或字段不兼容时转人工，不再回退到第一条标量字段。绑定是单次扫描快照授权：不读取、存储或哈希输入值；任何被观察到的页面变化、iframe 加载、页面输入/选择、重新打开或手动重扫都会清空绑定与重复项勾选，结构完全相同的复用节点也不继承旧绑定。只有用户刚选择绑定所触发的受控刷新可以保留该次绑定。
- 点击填写前会为每个缓存目标重新扫描并核对节点身份、连接/可见/空白/启用状态、适配器忽略规则、控件语义与类型、选项和重复上下文；任一变化都跳过且提示过期项，不覆盖页面或用户刚写入的值。
- 同一 document 内多个字段命中同一档案 key、且至少一个没有明确重复上下文时，所有相关字段转人工；这覆盖重复学校/经历容器漏识别，以及一项已识别、一项漏识别的混合情况。
- 原生 select 的第 0 项只有 value 为空时才视为 placeholder；非空第 0 项属于已有值。有效 `:disabled`/禁用 fieldset、祖先 `aria-disabled` 与 `aria-readonly` 均阻止自动填写。
- 自定义动态下拉在没有真实页面选项与事件链证据时始终转人工；隐藏附件只有在附近有界表单/上传容器内找到可见代理时才列为人工，始终不代用户选择或上传。
- 档案只有 `YYYY-MM` 时只能填写月控件；页面要求完整 `date` 时转人工，不会臆造每月 1 日。
- 同源 iframe 会纳入同一轮扫描并使用对应 document 的原生事件；每个已扫描 document 都监听其下 iframe reload，以使嵌套 reload 同样清空绑定并重扫。跨域或未加载 iframe 只显示脱敏人工提示。真实 ATS iframe 回归仍未完成。

### P1：结构化档案

- 已实现工作、实习、项目、教育和获奖的可增删多条记录，并在填写时兼容为长文本。
- 下一项是为记录增加拖拽排序、主记录标记和填写目标选择。
- 建立中英文统一字段模型，支持同一用户保存多套求职档案。
- 增加附件保险箱和上传前确认，但不默认自动选择文件。
- 支持 OCR，但必须明确提示是否使用本地模型或远端服务。

### P1：岗位上下文与 AI

- 只在用户确认后提取 JD 的有限文本，用来选择相关经历和关键词。
- 提供“技术严谨、业务结果、外企克制、初创主动”等可解释风格，而不是不可控的“吹牛强度”。
- 已实现 AI 输出的原文/改写对比，以及对新增数字和日期的启发式警告；建议文本是用户显式触发的可选项，可在面板内编辑后再填写。代码不能严格保证事实不变，数字及非数字事实都必须人工对照原文核验。
- 重复记录只允许对 `description` 正文显示 AI 润色入口；公司、岗位、学校、项目名、地点和日期等事实字段保持原值核对，不允许润色。
- 下一项是对新增专有名词和企业名称做更严格的事实核对。
- 为企业定制规则设置过期时间，防止旧偏好长期污染后续申请。

### P2：质量与运营

- 本地申请台账：公司、岗位、日期、所用档案版本、用户是否提交；不记录页面敏感值。
- 兼容性诊断包：只导出脱敏后的字段标签、控件类型和适配结果。
- 站点回归夹具：使用自建 HTML 表单模拟主流 ATS，不保存真实招聘页面或用户数据。
- `tests/fixtures/ats-page-validation.json` 只是公开入口到登录墙的脱敏证据和降级决策回放，不包含页面 DOM，也不能当作 DOM fixture 或真实字段覆盖证据。
- 当前脱敏契约只能证明失效时安全降级。待有脱敏测试账号后，仍需分别记录 Moka、北森、字节真实申请表的字段级正确、人工降级和误填数量，且保持最终提交由用户完成。
- 发布 Chrome Web Store 与 Edge Add-ons 前，补齐隐私政策、权限说明、数据删除说明和供应链审计。

## 不做的事情

- 不绕过验证码、登录、风控或反自动化机制。
- 不自动同意隐私政策或自动提交申请。
- 不从页面读取密码、验证码、身份证件附件和支付信息。
- 不提供虚构经历、学历、奖项或量化成果的功能。
