# 产品与执行架构

## 一个主流程

谷谷网站管理用户唯一的网申简历；扩展打开时展示这份简历，点击“开始填写”才扫描和写入表单。没有预匹配门槛、勾选清单或每次滚动的重新识别。

1. 第一方登录桥接把凭据交给扩展后台；后台一次请求服务器快照。
2. 后台在浏览器 session 缓存原始、经校验的协议数据；每次返回内容脚本前投影为可用简历。不能把投影结果再次当原始协议解析。
3. 未登录时是紧凑登录卡；登录后展示资料的可编辑本页副本。用户点开始后，按 DOM 顺序访问控件，现场读取标签、类型、所属经历，再从本页副本查值并写入。临时修改优先，不回写网站、不改变其他标签页；清空字段后不回退服务器旧值。
4. 原有队列处理期间，仅结构变化时补充发现；在页尾有限滚动以发现懒加载字段。空闲时不监听 scroll/input/change，不观察整个表单。
5. 每次普通控件先聚焦、写入并触发 input/change，真实失焦触发 blur/focusout，随后两次延迟核对；失败尝试恢复原值或空白。无法确认时记录失败，不伪报已填写。
6. 开始按钮运行中变成停止。刷新资料、编辑、撤销、退出、调试信息放在更多菜单。

## 模块

- `background.ts`：第一方登录、私有持久身份、会话资料缓存、同账号并发请求合并、退出/账号变化通知。
- `profile-snapshot.ts` / `resume-data.ts`：服务端协议校验和简历显示投影，实习/工作分开，历史细分描述合并。
- `sequential-fill.ts`：控件遍历、就近标签与经历上下文、逐项缓存取值、写入和核对。
- `dom-safety.ts` / `site-adapters.ts`：通用 DOM 读取、控件事件和局部标签兼容规则；不是必须整页命中才允许开始的模板。
- `content.ts`：闭合 Shadow DOM 简历面板，不把个人资料插入招聘页面的业务 DOM。
- `structure-report.ts`：用户主动复制的闭集结构报告。

## 执行约束

- 不调用提交、暂存、下一步、协议或上传按钮；密码、验证码、证件、付款、承诺与证明人信息不自动填写。
- 普通文本可覆盖；失败尝试恢复原值。原生选择组只处理未选择项，选项精确匹配。标准自定义下拉仅在能确定唯一弹层和唯一选项时点击；复杂级联、日期面板和未知控件留给用户。
- 原生控件核对的是即时保留，不代表招聘网站已经保存。自定义下拉不宣称可撤销；更多菜单的撤销仅覆盖成功的普通/原生控件。
- 重复经历优先利用记录容器；没有容器时按相同字段再出现来推进记录顺序。不把第一条经历复制到所有行；资料缺少下一条时留空。不会自动点击添加经历。
- 两分钟或 300 个控件结束一轮；最多 40 次懒加载滚动。不读取跨域 iframe 或封闭 Shadow DOM。
- 没有对应资料或语义冲突时跳过，不能用“能填写”代替真实事实。
- 会话缓存只在登录/缓存缺失/手动刷新时请求服务器。退出或切换账号使所有已打开面板取消运行、清除旧资料；空闲未打开页面不主动取资料。
- 有效 token 存入 `TRUSTED_CONTEXTS` 限制的扩展 local，内容脚本不能直接读取；JWT 有效期仅用于本地过期判断，不替代服务端认证。旧 session 凭据迁移与退出串行化；401 仅清除对应账号凭据，过期和退出同时清除资料。浏览器重启后身份保留、资料重新取一次。本页临时编辑只留在内存，刷新招聘页或刷新资料会清除。
- 调试只输出固定字段类别、结构类别和结果，不保存原始 DOM、URL、字段文案、简历值或凭据。

## 验证边界

合成 DOM、顺序执行和实际后台消息入口验证不等于北森/Moka 实际页面验证。真实 Edge 由用户操作和反馈；后续按实际失败的控件补充局部兼容，不重新引入主界面的匹配矩阵。
