# 谷谷网申助手（浏览器扩展）

独立运行于 Chrome / Microsoft Edge 的 Manifest V3 网申辅助扩展，不依赖油猴脚本。用户资料由谷谷网站按账号保存；扩展首次打开时检查登录，登录后一次拉取资料快照并放进浏览器会话缓存，用户点击后在本地逐项扫描并填写页面。

当前开发版本 `0.3.10`：

- 在 Moka、北森、字节、腾讯和阿里的职位/申请路由自动显示悬浮入口；点击前只判断站点与路由，不扫描表单。
- 用户在 `gudaya.chat` 登录、上传简历后一键写入或手工保存网申资料；扩展不持久保存简历或资料，只在当前浏览器会话缓存经校验的可填写字段。
- 当前填写链不把招聘页面字段发送到服务器。登录成功时只请求一次账号资料快照；页面扫描、语义匹配、逐项写入、即时核对和失败回滚均在扩展本地完成。手动点击“刷新资料缓存”或重新登录才会再次拉取资料。
- 重复经历必须显式绑定到具体资料记录；歧义字段、自定义动态下拉、附件、验证码和跨域 iframe 保持人工处理。
- 用户点击“一键扫描并填写”后，扩展对可匹配控件逐项复核并写入，最多四轮、六十项；表单新出现的空白字段在下一轮继续处理。页面已有普通文本默认参与，用户可取消勾选覆盖，或在字段列表排除具体字段。不会点击招聘网站的提交按钮，也不自动勾选协议。
- `0.3.1` 修复了 `0.3.0` 内容脚本被错误构建成 ES 模块、导致 Edge 报“Receiving end does not exist”的问题。
- `0.3.2` 修复空资料/未登录时的版本号比较错误，避免侧栏永久停在“正在检查”。
- `0.3.3` 让“重新识别”先重新检查资料服务；接口故障不再被误写为“尚无已发布资料”。
- `0.3.4` 将服务端 404、首次无资料、草稿待发布和已发布资料区分展示；404 时不再显示会跳到首页的上传按钮。打开资料页会先核对接口，再经过网站统一登录页同步同一账号。
- `0.3.5` 增加本次显式“覆盖已有文字”：只处理普通文本类控件，服务端必须回认覆盖权限；预览标出将覆盖的字段，页面旧值变化则停止该字段，填写后可撤销。原文字不上传服务端。
- `0.3.6` 补齐北森 `we.zyt.com/form?jobAdId=…` 的静态注入、申请页路由识别和北森适配器；其他 `zyt.com` 子域和非申请表路由不自动显示入口。
- `0.3.7` 的状态提示与网站的一键写入、保存即同步流程保持一致；服务端仍使用版本号使旧预览失效。
- `0.3.8` 针对北森截图呈现的相邻列式布局补充就近标签识别；无可填空白时明确提示已有文字默认跳过。侧栏新增本机诊断日志，记录识别、服务端计划和填写的固定类别与数量，帮助区分“无控件、已填值、语义未知、资料未匹配”；真实页面字段级效果仍需更新扩展后复核。
- `0.3.9`：用户在真实北森页面反馈 0.3.8 写入了错误字段，因此临时关闭北森写入，保留只读预览与诊断。诊断中的“人工项为主”也不再误标为“已有文字”。
- `0.3.10`：按用户要求恢复北森页面由按钮主动触发的写入，并改为从上到下多轮扫描、逐项写入和即时核对。失败的空白控件尝试清空，覆盖旧值失败则恢复原值；若控件被页面替换、无法确认恢复，明确提示人工检查。登录成功后一次拉取并会话缓存服务端资料，填写循环不再请求服务端计划或版本校验。诊断增加脱敏控件结构报告，只输出封闭类别，不输出 DOM 原文或填写值。即时保留仍不能证明招聘网站已保存。

## 本地安装

要求 Node.js 22+。

```bash
npm ci
npm run check
```

然后打开：

- Chrome：`chrome://extensions`
- Edge：`edge://extensions`

启用“开发者模式”，选择“加载已解压的扩展程序”，加载本仓库的 `dist/` 目录。

更新已加载的开发版时，先运行 `npm run check` 重建 `dist/`，在 `edge://extensions` 点击该扩展的“重新加载”，然后刷新已打开的招聘页。扩展卡片应显示 `0.3.10`；只改源码或只刷新招聘页不会更新已加载的脚本。

## 使用流程

1. 在谷谷网站登录，打开“网申资料”，上传简历后预览并一键写入；手工编辑会自动同步，无需另点保存。
2. 打开受支持招聘网站的职位或申请页面，点击右下角“谷”悬浮入口；未知站点可点击扩展图标临时打开。
3. 如扩展尚未同步登录，按提示打开谷谷登录页完成授权。登录成功后扩展一次性缓存当前个人资料；同一浏览器会话内复用，不在每次扫描或填写前请求服务器。网站资料有修改时，手动点“刷新资料缓存”。
4. 在侧栏点击“一键扫描并填写”：扩展按页面 DOM 顺序逐项扫描和填写，自动继续处理新出现的空白字段。已有普通文本默认允许覆盖；取消顶部勾选可只填空白，列表中的勾选可排除具体字段。重复经历仍需先绑定具体资料记录；动态下拉和附件留给人工。
5. 查看即时写入结果与页面实际内容，必要时点“撤销本轮”；是否保存或提交网申由用户自行决定。

排查识别问题时，展开侧栏底部的“诊断日志”，填写后使用“复制诊断”和“复制脱敏结构”。前者只保留最近 80 条、最长 24 小时的本机浏览器会话记录；后者仅在用户点击时读取并复制当前可见控件的类型、标签来源、语义类别、字段匹配与写入结果（最多 80 行），不会持久保存。两者都不包含招聘网址、字段原文、输入值、简历、账号或原始错误。可在侧栏点“清空日志”。

## 数据与服务端边界

登录只发生在 `gudaya.chat` 第一方页面。登录桥接成功后，扩展后台请求一次 `/api/autofill/profile/snapshot`，把 token 和经过结构校验的个人资料保存在 `chrome.storage.session`；浏览器会话结束、退出账号或重新登录即清除。招聘页面内容脚本拿不到 token，只使用本次会话快照做本地匹配。用户主动点“刷新资料缓存”时才重新请求快照。旧版 `/plan` 与 `/validate` 接口暂为兼容保留，0.3.10 的填写链不调用它们。

网站资料尚未保存、服务端版本不兼容、页面字段结构不确定、计划版本变更时，扩展保持人工处理或停止填写，不回退到本地档案猜填。

## 隐私与权限

- `activeTab`：用户点击扩展时，临时读取和填写当前页面。
- `scripting`：将字段识别面板注入当前页面。
- `storage`：在浏览器会话中暂存扩展登录 token、经过校验的个人资料快照和有界诊断计数；不写入持久化存储。退出、重新登录或浏览器会话结束即清除。结构报告只在用户点击时复制，不持久保存；诊断不上传服务器。
- 受支持招聘域名的静态内容脚本：让悬浮入口能够随职位/申请页面自动出现。点击前只读取 URL、标题和路由；完整表单扫描仍由用户打开助手或选择简历后触发。
- `https://gudaya.chat/*` 与 `https://www.gudaya.chat/*`：打开第一方登录、验证会话并代理网申资料与填写计划 API。登录 token 不会返回给招聘页内容脚本。

不要在 Issue、日志、测试夹具或提交中放入真实简历、身份信息或 API Key。

## 准确性契约

`src/field-matcher.ts` 是唯一字段语义与控件匹配入口。它按 label、ARIA label、placeholder、name 的确定性证据计算结果；`type=email/tel` 只是低置信度提示，不能覆盖相冲突的 label。下拉、radio 和 checkbox 不使用 substring 猜选项，多选部分命中会整体转人工。

原生 select 只有当前值为空时才视为 placeholder；即使 `selectedIndex === 0`，非空真实选项也属于已有值，不会被覆盖。`:disabled`（包括禁用 fieldset 的有效状态）、自身或祖先的 `aria-disabled`，以及 `aria-readonly` 都会使控件退出自动填写。

`tests/fixtures/field-matcher.json` 使用 60 条脱敏案例覆盖中英文基础字段、城市/地址、教育字段、重复经历显式绑定、单选/多选、重复选项值拒绝、动态下拉、附件、日期精度、URL、高风险字段和各种跳过状态；`tests/fixtures/ats-page-validation.json` 只保存 3 条不含 DOM 和页面正文的平台入口证据及安全降级回放，它不是 DOM fixture。DOM 安全测试使用自建 Fake DOM，直接覆盖同源/嵌套 iframe 监听、跨域 iframe 人工降级、隐藏附件的有界代理判断、跨重复根 radio 拒绝、checkbox 行隔离、重复语义漏识别降级、radio/checkbox/select 重复值零写入、select/有效禁用状态、扫描 epoch 失效、填写前目标复核和人工项身份去重。它们是协议回归，不是任何真实 ATS 的准确率结论。

2026-10-10 对 Moka、北森和字节公开职位入口做了无账号、无提交的只读验证：三者的职位列表和详情均可访问，但点击申请后都进入登录墙，因此按安全边界停止。未看到登录后的真实申请表，也未验证真实重复经历组、动态下拉、附件或 iframe 的字段级准确率；本轮新增的这些能力只具有脱敏契约和构建证据，不能据此宣称三个平台已经真实可用。

2026-10-12 用户在已登录的三只松鼠 Moka 申请页点击 `0.3.0` 的“识别当前页面”，报告 `Could not establish connection. Receiving end does not exist`。本地构建检查确认当时 `content.js` 含顶层 ES 模块 `import`，导致普通内容脚本无法启动。`0.3.1` 改为独立 IIFE 打包。用户安装 `0.3.2` 后，真实 Edge 新标签确认悬浮入口和侧栏可打开，未登录提示不再卡住；用户扫码后扩展自动同步会话，服务端 v2 资料接口返回 404，侧栏明确停用填写。点击“重新识别”仍把接口故障描述成“尚无已发布资料”，已在 `0.3.3` 修正文案与重试行为。随后确认网站资料入口跳转首页、登录页二维码过期但网站已有登录；`0.3.4` 与配套网站分支已在本地修正状态分流和扫码登录流程。用户重载 0.3.4 后，再次在 Edge 的 Moka 申请页确认扩展悬浮入口已注入；0.3.5 覆盖能力仍只通过脱敏合成控件与协议测试，线上尚无 v2 资料接口。未填写或提交。

## CI 与发布

扩展仓库使用 Node.js 22；推送 `main`、`codex/**` 分支或创建 PR 时，CI 执行 `npm ci && npm run check`。`check` 包括 TypeScript、Node 契约测试和 Vite 构建。

当前没有 Release、浏览器商店上传或签名工作流。当前开发版本为 `0.3.10`，本地 `dist/` 仍只是开发验证产物；合并、打标签或商店发布需要单独完成并验证。

## 当前限制

- 扫描版 PDF 暂不做 OCR。
- MVP 不会主动点击招聘网站的“添加经历”，只填写已经渲染出来的字段。
- 当前站点适配器覆盖通用规则、Moka、北森、字节跳动、腾讯和阿里巴巴的常见字段语义；登录后的具体申请页仍需逐站点回归。
- 自动悬浮入口当前只对上述已知招聘域名开放；未知企业自建站必须由用户点击扩展图标临时启动，不申请 `<all_urls>` 常驻权限。
- 资料与填写计划需要服务端 v2 接口和网站资料页配套部署；只安装扩展不能使用未部署的接口。
- Moka、北森和字节公开职位入口已验证到登录墙，真实申请表字段尚未验证。
- 自定义动态下拉在真实页面证明精确选项和事件链前只会提示人工处理；跨域 iframe 和封闭 Shadow DOM 保持人工。
- 不自动上传简历附件；可见附件控件会明确列为人工处理，避免误传文件。
- 一档解析是规则提取；复杂版式需要用户补充，或后续显式使用 AI 结构化解析。
