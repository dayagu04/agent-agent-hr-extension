# 谷谷网申助手（浏览器扩展）

独立运行于 Chrome / Microsoft Edge 的 Manifest V3 网申辅助扩展。它不依赖油猴脚本，也不依赖 `agent-agent-hr` 服务端。

当前 `0.1.0` 是可安装的 MVP：

- 在浏览器本地维护个人档案；
- 导入 PDF、DOCX、TXT、Markdown 或 JSON 简历，并在本地提取文本和常用字段；
- 将教育、实习/工作、项目和获奖维护为可增删的结构化记录，并兼容旧长文本；
- 用户点击扩展后，识别当前招聘页面中的可见空白字段；
- 展示字段、匹配内容和置信度，由用户勾选后再填写；
- 按招聘站点选择适配规则，覆盖通用、Moka、北森、字节、腾讯和阿里，监听动态表单并增量刷新识别结果；
- 重复教育、工作和项目行必须先显式绑定到一条结构化档案记录，不会默认取第一条经历；绑定同时校验行位置、结构属性和字段结构，不读取输入值，节点复用、换序、替换或新增导致签名变化时会清除绑定与勾选并要求重新选择；
- 自定义动态下拉在选项和事件链未被真实验证前保持人工选择；附件控件明确提示人工核对；
- 同源 iframe 递归扫描，跨域或尚未加载的 iframe 明确转人工，不静默忽略；
- 低置信度字段默认不勾选，并支持撤销最近一轮填写；
- 城市与详细地址分别建模，单选/多选/下拉只接受精确规范化选项；
- 未知、歧义、控件不兼容和缺少档案值的可见必填项会计入“需人工处理”，不会静默漏填；
- 可选配置 OpenAI 兼容接口，只对开放题以及重复经历中的描述正文逐项润色；公司、岗位、学校、项目名和日期等事实字段不显示润色入口；
- AI 改写以原文/建议对比方式展示，并标记建议中新增的数字和日期；
- 不自动提交申请，不自动勾选协议，也不在后台持续读取网页。

## 本地安装

要求 Node.js 22+。

```bash
npm ci
npm run check
```

然后打开：

- Chrome：`chrome://extensions`
- Edge：`edge://extensions`

启用“开发者模式”，选择“加载已解压的扩展程序”，加载本仓库的 `dist/` 目录。

## 使用流程

1. 打开扩展的“编辑个人档案”。
2. 导入简历或手动填写资料，校对后保存。
3. 打开招聘网站的申请页面，点击扩展图标，再点击“识别当前页面”。
4. 在页面右侧检查字段匹配和待填内容，取消不应填写的项目。
5. 可选地逐项调用 AI 润色，再点击“填写已选字段”。
6. 在招聘网站中人工检查并手动提交。

## 两档能力

### 一档：本地识别与填写

一档不需要账号和服务端。档案及简历提取文本存储在 `chrome.storage.local`，字段识别在当前页面内完成。扩展只在用户主动点击后获得当前标签页的临时访问权。

### 二档：AI 辅助润色

用户自行配置 OpenAI 兼容 API 地址、模型和 Key，并单独授权该接口域名。每次润色只发送：当前字段问题、待润色原文、页面标题和域名；不上传整张页面。

AI 的职责是调整结构、措辞和岗位侧重点，而不是制造事实。提示词明确禁止新增无法由原始资料支持的单位、学历、职责、日期、奖项和数字，最终结果仍需用户确认。

## 隐私与权限

- `activeTab`：用户点击扩展时，临时读取和填写当前页面。
- `scripting`：将字段识别面板注入当前页面。
- `storage`：在本机保存档案和设置。
- AI 接口域名是可选权限，只在用户点击授权时申请。
- API Key 默认只保存在浏览器会话；“持久保存”需要用户主动勾选。浏览器扩展存储并不是加密保险箱。

不要在 Issue、日志、测试夹具或提交中放入真实简历、身份信息或 API Key。

## 准确性契约

`src/field-matcher.ts` 是唯一字段语义与控件匹配入口。它按 label、ARIA label、placeholder、name 的确定性证据计算结果；`type=email/tel` 只是低置信度提示，不能覆盖相冲突的 label。下拉、radio 和 checkbox 不使用 substring 猜选项，多选部分命中会整体转人工。

`tests/fixtures/field-matcher.json` 使用 56 条脱敏案例覆盖中英文基础字段、城市/地址、教育字段、重复经历显式绑定、单选/多选、动态下拉、附件、日期精度、URL、高风险字段和各种跳过状态；`tests/fixtures/ats-page-validation.json` 只保存 3 条不含 DOM 和页面正文的平台入口证据及安全降级回放，它不是 DOM fixture。DOM 安全测试使用自建 Fake DOM，直接覆盖同源 iframe 匹配与填写、跨域 iframe 人工降级、隐藏附件代理判断、人工项身份去重，以及重复行节点复用/换序后的绑定失效。它们是协议回归，不是任何真实 ATS 的准确率结论。

2026-10-10 对 Moka、北森和字节公开职位入口做了无账号、无提交的只读验证：三者的职位列表和详情均可访问，但点击申请后都进入登录墙，因此按安全边界停止。未看到登录后的真实申请表，也未验证真实重复经历组、动态下拉、附件或 iframe 的字段级准确率；本轮新增的这些能力只具有脱敏契约和构建证据，不能据此宣称三个平台已经真实可用。

## CI 与发布

扩展仓库使用 Node.js 22；推送 `main`、`codex/**` 分支或创建 PR 时，CI 执行 `npm ci && npm run check`。`check` 包括 TypeScript、Node 契约测试和 Vite 构建。

当前没有 Release、浏览器商店上传或签名工作流。版本仍为 `0.1.0`，本轮不打标签、不发布；本地 `dist/` 只能作为开发验证产物。

## 当前限制

- 扫描版 PDF 暂不做 OCR。
- MVP 不会主动点击招聘网站的“添加经历”，只填写已经渲染出来的字段。
- 当前站点适配器覆盖通用规则、Moka、北森、字节跳动、腾讯和阿里巴巴的常见字段语义；登录后的具体申请页仍需逐站点回归。
- Moka、北森和字节公开职位入口已验证到登录墙，真实申请表字段尚未验证。
- 自定义动态下拉在真实页面证明精确选项和事件链前只会提示人工处理；跨域 iframe 和封闭 Shadow DOM 保持人工。
- 不自动上传简历附件；可见附件控件会明确列为人工处理，避免误传文件。
- 一档解析是规则提取；复杂版式需要用户补充，或后续显式使用 AI 结构化解析。
